LSJ: The JSL Mirror
=================================


LSJ is a tool for performing the compile-time reflection required for the ``Interface`` module of the [JSL](https://github.com/DrFraserGovil/JSL). 

When run on a file, the LSJ detects POD structures which have been declared a part of the JSL::Interface::Aggregator pattern, and generates a ``FieldList`` for them, allowing for runtime modification and parsing of arguments and configuration files. 

The field list for each class is written to a file (usually ``targetfile.classname.autogen``) in the same directory as the target file, and a suitable ``#include`` appended to the class (if not already present). The class definition and comments within it act as the metadata to infer the structure of the autogenerated files, and hence the configuration routine.

The LSJ is designed to allow a user to integrate it into their compilation routine, with the source code for the parsers being a valid C++ file. This means an LSP can track newly added symbols without needing to wait for a compilaton call, or having a dynamic file watcher.

Install
--------

This tool can be acquired in the following way:

```
git clone git@github.com:DrFraserGovil/LSJ
cd LSJ
make
```

Compiling this requires either a copy of the JSL library to be on your $PATH, or an internet connection sufficient for the ``FetchContent`` directive to clone a copy to the build directory.
  
Usage
----------

Basic usage:

```
./lsj target1.h target2.h ... 
```

When multiple files are passed to a single instance, they are assumed to be associated with the same project, and so errors and warnings will surface if aliases are shared between variables across files. 

The LSJ is bootstrapped, and uses an LSJ-written interface to provide runtime modification of its behaviour:

Syntax
---------------------

LSJ uses a doxygen-like syntax to convert POD classes into configurable entities in a nested heirarchy. 

In order to trigger the parser, an instance of the [JSL::Interface::Aggregator](https://jack-standard-library.readthedocs.io/en/latest/docfiles/interface/aggregate.html#aggregate) must be declared - but without an instance of the ``FieldList`` member (since that is what is being generated by the tool). 

```
//! @name [Display Name] <- the name assigned to this block in the Help Menu
//! @command [cmd1] [docstring] <-- command strings which appear in the Help Menu
//! @command [cmd2] [docstring] <-- command strings which appear in the Help Menu
class Object : public JSL::Interface::Aggregator<Object>
{
    public:
       // @brief [docstring] <-- appears in the Help menu
       //! @name [name] <-- Used for display purposes in the Help menu
       //! @alias [list] <-- alias used in config files (space or comma-separated list)
       type Name = defaultValue;

       //or equivalently...
       /*! @brief [docstring]
          @detail [continue docstring with a newline inserted]
          @alias [list]
          @alias [list to be appended]
       */
       type2 Name2; <-- initialised with empty '{}'


       NestedObject Nested; <--- If Nested is also a Aggregator in the input files, this will be captured automatically
}

```

Notes
++++++++

1. Members which do not declare a ``@alias`` and ``@brief`` field **will be omitted** from the reflection pipeline; this allows some 'static' members which cannot be altered.
2. Metadata for a class or a field must be declared in lines directly above the element they are referring to; blank lines sever the connection. 
2. The ``!`` is optional (but recommended as it allows automated inclusion of the ``@brief`` and ``@detail`` field with doxygen, and doxygen-aware editors)
3. The ``@name`` field is optional; if absent the typename is used (for classes) or the symbol name (for member fields)
4. Nested Aggregators are automatically included, as long as the aggregator is declared within the list of files supplied to the LSJ
5. Typenames and default values are copied verbatim; there is no checking if they are actually valid. LSJ does not convert invalid C++ classes to valid ones.
6. Running with the ``--fix`` flag will allow the following errors to be corrected in the source file
  * Missing 'public' from inheritance
  * Missing CRTP (i.e. Aggregator -> Aggregator<Object>)
7. Duplicate aliases will be omitted (with an error message) from all subsequent fields. If this results in a field having no valid aliases, it will be omitted from the reflection output. Duplicate aliases are tracked across all files. 
8. Doxygen fields not associated with member variables (i.e. ``@return`` or ``@param``) will cause the member to be ignored.
9. We do *not* prevent the capture of non-modifiable fields (i.e. static or const); your compiler will shout at you instead.
